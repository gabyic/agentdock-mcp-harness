# AgentDock MCP Harness v0.2.0-rc.1

> **无限流 / Infinite Coding Flow** — use your existing ChatGPT / Claude Web quota for remote coding without a second server-side API token meter.

This is the first release candidate for the v0.2 productionization line. It freezes the v0.2 P0 feature set for release validation; no new product features are planned between this RC and v0.2.0 unless a release blocker is found.

## Highlights

- MCP TypeScript SDK v2 and MCP 2026-07-28 modern-era support.
- Backward-compatible 2025-era stdio/HTTP client support.
- Native stateless Streamable HTTP while retaining stdio.
- Shared durable AgentDock runtime across stateless HTTP requests.
- Versioned JSON configuration schema with environment overrides.
- `agentdock doctor` deterministic diagnostics.
- `agentdock health` health/readiness checks with retry windows.
- Managed install / upgrade / uninstall lifecycle.
- Default uninstall preserves durable Task state and configuration.
- Reproducible Git-based release tarballs with SHA-256 checksums.
- Hardened service lifecycle with graceful SIGTERM and crash recovery.
- systemd contract fixed to `Restart=always` and `KillMode=control-group`.
- Planned service shutdown records owned Processes as `CANCELLED`.
- Unexpected loss of Process ownership restores persisted Processes as `INTERRUPTED`.
- No server-side LLM, autonomous worker, or second AI API key is introduced.

## Release gate

The RC is required to pass the same deterministic gate used by the tag-driven GitHub Release workflow:

```bash
npm run release:gate -- v0.2.0-rc.1
```

The gate covers:

- Node.js 24;
- package / lockfile / runtime-version consistency;
- tag/version consistency;
- dated CHANGELOG entry and release notes;
- `private: true` npm publication guard;
- full MCP black-box test suite;
- v0.1 acceptance scenario;
- production dependency audit;
- systemd service contract;
- reproducible release artifact comparison;
- SHA-256 checksum verification;
- extracted archive installation;
- installed CLI version/doctor checks;
- installed systemd-unit validation;
- native HTTP startup, health and graceful shutdown smoke.

## Installation

Download both release assets and verify the checksum:

```bash
sha256sum -c agentdock-mcp-harness-v0.2.0-rc.1.tar.gz.sha256
tar -xzf agentdock-mcp-harness-v0.2.0-rc.1.tar.gz
cd agentdock-mcp-harness-0.2.0-rc.1
./scripts/install.sh
```

Then verify the environment:

```bash
agentdock version
agentdock doctor
```

For native HTTP:

```bash
agentdock health
```

## Upgrade

A managed installation can be upgraded from an extracted trusted RC directory:

```bash
agentdock upgrade --source /path/to/agentdock-mcp-harness-0.2.0-rc.1
```

Upgrade does not automatically download code and does not remove durable state or configuration.

Existing environment-based v0.1/v0.2 development deployments remain supported by the v0.2 config compatibility layer.

## Service deployment

The release contains:

```text
deploy/systemd/agentdock-http.service
```

Validate the unit contract with:

```bash
npm run service:verify
```

The recommended Core deployment is native HTTP bound to loopback behind authenticated TLS/OAuth ingress.

## Known boundaries

- Linux is the supported execution host.
- macOS and Windows execution backends are not included.
- Public TLS/OAuth ingress remains an external deployment responsibility.
- AgentDock inherits native OS permissions; it is not a sandbox.
- No autonomous Codex/Claude/OpenCode worker or server-side LLM is included.
- Push/merge/PR/deploy are not first-class Core primitives.
- npm publication remains disabled for this RC.

## Stable v0.2.0 promotion

The stable v0.2.0 release should be cut from the RC line after:

- no unresolved release-blocking regression;
- CI and release gate remain green;
- release archive installation is re-verified;
- production HTTP/service restart smoke remains green;
- any RC fixes are documented and re-cut as a new RC before stable promotion.
